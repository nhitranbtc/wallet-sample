# Manual testnet verification — Release 1

This is a hands-on checklist that **complements** the automated
`cargo test --workspace` contract. Run every step on a real iOS or
Android device with biometrics enrolled. Do not run any of this on
an emulator — biometric hardware is required for the destructive and
signing flows.

## Preconditions

- **Device**: iOS 16+ or Android 12+ with Face ID / Touch ID / fingerprint
  enrolled and **not** opted into "Always allow" for the wallet app.
- **Build**: install the Release-1 build of `flutter_app/` from the
  `wallet-sample/rust` workspace compiled with
  `flutter_rust_bridge`.
- **Testnet faucets** (test tokens only — never send mainnet funds):
  - **Sepolia ETH** — `https://sepoliafaucet.com` or
    `https://cloud.google.com/application/web3/faucet/ethereum/sepolia`.
  - **Bitcoin testnet BTC** — `https://testnet-faucet.mempool.co`
    or `https://bitcoinfaucet.uo1.net`.
- **Explorers**:
  - Sepolia: `https://sepolia.etherscan.io`.
  - Bitcoin testnet: `https://mempool.space/testnet`.

## Per-chain steps

### Ethereum (Sepolia)

1. Launch the wallet. Confirm a real OS biometric prompt fires for
   the initial unlock.
2. Tap **Create wallet** (or **Restore** if you already have a Sepolia
   test vector). A new biometric prompt must fire — the
   `restore_wallet_via_native_surface` path is gated on the platform
   secure-storage shim.
3. Tap **Receive**. Copy the Sepolia receive address (starts with
   `0x`). Confirm the address matches the one displayed in the
   in-app **Account details** screen.
4. From an external Sepolia wallet, send **0.0001 ETH** to that
   address from the testnet faucet. Wait for one confirmation.
5. Tap **Send** → **Ethereum**. Enter the destination address (any
   other Sepolia address you control) and an amount of **0.00005 ETH**.
6. Tap **Review**. A biometric prompt must fire for
   `authenticate_sign_and_broadcast`. **Do not** dismiss it without
   authenticating — the `SigningCoordinator` will refuse to consume
   the proof otherwise.
7. After broadcast, the app should show a pending status; poll until
   the Sepolia explorer shows ≥ 1 confirmation.
8. Tap **Lock wallet**. A fresh biometric prompt must fire (lock is
   a destructive coordinator path). Verify the wallet UI now shows
   the locked state.
9. Tap **Remove wallet**. A fresh biometric prompt must fire (wipe
   is a destructive coordinator path). Confirm the wallet reports an
   empty state.

### Bitcoin (testnet)

10. Re-create or restore the wallet (a fresh `uuid` is fine; the
    mnemonic is regenerated by `create_wallet`).
11. Tap **Receive** for Bitcoin. Confirm the address starts with
    `tb1` (bech32 testnet).
12. From the testnet faucet, send **0.00001 tBTC** to that address.
    Wait for at least one confirmation on
    `https://mempool.space/testnet`.
13. Tap **Send** → **Bitcoin**. Enter the destination tb1 address
    and an amount of **0.000005 tBTC**.
14. Tap **Review** → authenticate. Verify the same biometric prompt
    flow as Ethereum.
15. After broadcast, confirm the txid appears in
    `mempool.space/testnet` and progresses to ≥ 1 confirmation.

## Verification checklist

For every step above, tick the box only after the behavior is
observed. If any box cannot be ticked, file a bug with the device
model, OS build, and `flutter logs` / `adb logcat` / Xcode console
output — **never paste the mnemonic or any signed payload** in the
report.

- [ ] Recovery UI never appears in the iOS / Android app-switcher
      snapshot. (Switch to the home screen mid-recovery and verify
      the recovery prompt does not render in the snapshot, only the
      platform's lock screen.)
- [ ] No secret material in `flutter logs`, `adb logcat`, or the
      Xcode console. Specifically: no mnemonic phrases, no WIF keys,
      no raw seed bytes, no signed-transaction payloads, no
      `BiometricProof` values.
- [ ] Both transactions confirmed in the respective explorers
      (Sepolia and Bitcoin testnet).
- [ ] Each signature required a fresh biometric prompt — i.e. you
      could not queue multiple `authenticate_sign_and_broadcast`
      calls back-to-back without re-prompting.
- [ ] Each destructive operation (`lock_wallet`, `remove_wallet`)
      required a fresh biometric prompt.
